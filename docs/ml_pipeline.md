# 🧠 EnergyIQ Machine Learning & Anomaly Pipeline Specification

## 1. Overview
The EnergyIQ Machine Learning Pipeline performs automated feature engineering, quantile baseline estimation, contextual anomaly detection via **Isolation Forest**, and heuristic **Fault Linking Interpretation**.

---

## 2. ML Architecture Flow

```text
Raw Telemetry (kWh, State, Output, Temp, Maintenance Days, Microgrid)
                          │
                          ▼
            Feature Engineering & Preprocessing
   (norm_expected_kw, historical_dev_pct, Z-Score, Ratios)
                          │
                          ▼
           Isolation Forest Anomaly Detector
  (Contamination = 0.05, Normalized Anomaly Score 0-100)
                          │
                          ▼
             Fault Linking & Evidence Engine
    (Rule Matrix, Physical Context, Confidence Score %)
```

---

## 3. Data Leakage Prevention
To guarantee strict evaluation integrity:
- `is_anomaly` and `fault_label` ground-truth labels are **never** included in feature engineering or model training matrices.
- Models are fitted strictly on contextual telemetry features (`energy_kwh`, `operating_state`, `production_output`, `temperature`, `maintenance_days`, `solar_generation_kwh`, `battery_soc`, `grid_consumption_kwh`).

---

## 4. Baseline Power Calculation (`norm_expected_kw`)
To prevent multi-day gradual equipment degradation from skewing rolling mean baselines, EnergyIQ computes `norm_expected_kw` using the **25th percentile of `ON` operating state energy** per asset over historical windows.

$$Z = \frac{x_{\text{energy}} - \mu_{\text{baseline}}}{\sigma_{\text{baseline}}}$$

---

## 5. Model Signal vs Fault Linking Interpretation

### A. Model Signal (Contextual Isolation Forest)
Generated by Scikit-Learn `IsolationForest(n_estimators=100, contamination=0.05)`.
Outputs:
- Decision function score
- Normalized Anomaly Score $[0, 100]$
- Severity Classification (`NORMAL`, `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`)

### B. Fault Linking Interpretation (Physical Rule Engine)
Decodes ML anomaly signals into 10 physical root-cause mechanisms:
1. `Mechanical Resistance`: Energy draw > +50% above expected while production rate is normal/high (`ON`).
2. `Motor Inefficiency`: Sustained energy draw +30% to +50% above expected with normal production output (`ON`).
3. `Sensor Malfunction`: Energy consumption reads 0.0 kWh while equipment is reported ON with active production output.
4. `Unexpected Standby Consumption`: Non-zero energy draw (> 2.0 kWh) while operating state is `OFF`.
5. `Excessive Operating Duration`: Running in active state `ON` during non-production off-peak hours/weekends.
6. `Cooling/Heating Inefficiency`: High HVAC/Chiller power draw under elevated ambient temperature (> 30°C).
7. `Production-Related Abnormality`: High energy draw (+25%) despite reduced production output (< 40 units).
8. `Maintenance Overdue`: Service interval > 60 days with elevated energy draw (+25%).
9. `Electrical Abnormality`: Severe short-duration energy spike (+65% above baseline).
10. `Unknown Anomaly`: Low-confidence fallback when physical evidence is unclassified.
